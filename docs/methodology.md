# 映射方法论

本项目把"大模型 ↔ 三国武将"的类比工程化。原则：**先看数据，再谈演义**。

## 一、两大史源

| 史源 | 内容 | 字段 |
|---|---|---|
| 三国志14 威力加强版（Nobuwiki 整理） | 1180 名武将 | 统率、武力、智力、政治、魅力、合计、主义、政策等 |
| Artificial Analysis 榜单快照 | 697 个模型、687 个有分（2026-10-10，leaderboard 单页全库） | Intelligence Index（II，浮点+估算标记）、每任务成本、输出速度、首字延迟 |

## 二、五维映射与权重

按项目约定，权重从高到低分三级：

### 一级权重（最高）：武力 ↔ 模型智力

- 三国志14的**武力**（单挑硬实力）对应模型的 **Intelligence Index**（峰值智能）
- 折算公式，以快照榜首 II 为 100 基准（当前榜首 = Claude Opus 5.5，II 57.6）：

  ```
  折算武力 = round(模型II ÷ 榜首II × 100)
  ```

- 匹配时使用**百分位距离**而非原始值：模型在模型群的 II 百分位 ≈ 武将在武将群的武力百分位
- 示例：GPT-6 Astra II 52.7 → 折算武力 91，与三国志14原版曹彰（武力 90）几乎重合——这是本方法论的"标志性验证"

### 二级权重：其他数值维度

| 三国志14维度 | 模型世界对应 | 当前数据源 | 状态 |
|---|---|---|---|
| 智力 | 性价比（成本反比：便宜会用计 = 智） | AA 每任务成本 | ✅ 已自动化 |
| 统率 | Agentic 带队能力（analystAgent / apexAgents / itbenchSre / gdpval 四项子分中非空项的均值） | AA 全库表内嵌子分 | ✅ 已自动化（2026-10-10） |
| 政治 | 指令遵循 / 对齐 / 不整活 | 对齐评测（无公认源） | ⏳ 人工评估 |
| 魅力 | 调用量 / 生态口碑 / 民心 | OpenRouter rankings 调用份额（2026-10-09~15 窗口） | ✅ 已自动化（2026-10-15） |

两条折算公式（与武力同构，榜首=100 基准）：

```
折算统率 = round(统率基准 ÷ 全库统率榜首 × 100)
折算智力 = round((1 − 成本百分位) × 100)   # 全库有成本模型排名，越便宜越有计
折算魅力 = round(调用量份额 ÷ 榜首份额 × 100)  # OpenRouter 全期 rankingMetricValue
```

叙事校验即成段子：吕布 $5.98/任务全库最贵档 → 折算智力 2（"惜赤兔太贵"，有勇无谋数值化）；曹彰 $3.26 → 智 8（黄须儿）；姜维三维 80/71/70 对原版 89/91/90（全能少年将军）。agentic 子分覆盖有限（gdpval 295/703、其余三项仅前沿模型），56/102 席有折算统率，空席记"无数据"。

魅力维度（2026-10-15 接入）：OpenRouter rankings/models 端点（`scripts/fetch_openrouter.py` 抓取留档 `data/openrouter_rankings_*.json`），94/102 席有值，slug 三级匹配（去日期精确→前缀→少量别名）。马超（DeepSeek V4.1 Flash）以 20.8% 份额居全库第一 → 折算魅力 100，"西凉铁骑白菜价"完成终极数值化；诸葛亮 V4 Pro 不上海外路由 → 魅力 0（"制裁下六出祁山"）。国内 API（ERNIE/Doubao/星火）不经 OpenRouter，相关席位天然无值。

自动匹配脚本中：`score = 0.7 × |II百分位 − 武力百分位| + 0.3 × |成本性价比百分位 − 智力百分位|`，分数越低越匹配。

### 三级权重（最低）：阵营与生平典故

- 阵营设定（曹魏=美国闭源阵营、蜀汉=中国大模型阵营、东吴=开源联盟、群雄=各路厂家诸侯会盟（吕布军、黄巾、南中均已并入））**只在数值接近时用作并列打破**
- **主公位 = 厂家/机构位**：主公只写公司名（曹操=OpenAI、刘备=幻方量化、孙权=Meta、袁绍=Anthropic、刘表=Google……），永不落具体模型、数值恒空；模型只能坐武将/诸侯位，退役与否写进列传注记（不设"已故"角色——严格说来三国武将都已作古）。群雄实行多主公制（袁绍领衔，吕布军、黄巾、南中均已并入）
- **血缘武将同厂商**：父子兄弟必须落在同一厂商的模型系（曹操诸子皆 OpenAI、关家满门 GLM、马家三骑 DeepSeek、孙氏兄弟 Meta、荀彧荀攸叔侄同门），跨厂牌只允许非血缘的结义或客将。此规则约束武将位；主公位是公司位，兄弟分属不同公司按"各立门户"记录（如袁绍 Anthropic / 袁术 Inflection）
- 生平典故（水淹七军 = 某事件、宛城之战 = 某模型换代）是叙事层，**不参与打分**
- 典故与史实的对应有大量"口径之争"（OpenAI 自家评测说 Astra 第一，AA 榜首是 Opus 5.5）——这类争议本身按"许田围猎"处理：各说各的，榜单为准

## 三、双轨映射

| 版本 | 规则 | 用途 |
|---|---|---|
| **天命版**（自动） | 纯强度百分位匹配，无视阵营 | 数据说话，输出 `suggestions_tianming.csv` |
| **演义版**（人工） | 阵营优先 + 主公位=厂家 + 血缘同厂商 + 强度约束（II 差距过大不许越级） | 叙事与传播，见 `mapping/mapping_v0.7.csv`（102 席，站点 `docs/index.html` 的数据源） |

两版允许冲突。例如：天命版里 Sonnet 5.5（II 56）的百分位对手是张飞/关羽级武将；演义版里它是陈宫（辅佐吕布军的军师）——因为吕布军需要军师，而陈宫原版智力 89、武力 55，恰好是"高智低武"的性价比型，与 Sonnet 便宜量大的定位吻合。

站点展示的是演义版。GPT-6 Astra 的演义席是曹彰（折算武力 91，原版 90），详情层标为数值锚点。`mapping/suggestions_tianming.csv` 是天命版脚本对照**更早的整数 II 表格导出**留下的建议（其中 GPT-6 Astra (max) 最近的是颜良，距离 0.004），与现行全库快照不是同一次计算，也不驱动展示页。

## 四、已知口径问题（务必阅读）

1. **AA II 偏重英文基准**：DeepSeek V4 Pro 在 Vellum HLE 口径登顶（48.2%），在 AA II 只有 36。本项目以 AA 为唯一主锚（史源唯一才可比），其他口径记入备注。有意思的是：诸葛亮原版武力仅 38，AA 口径的 DeepSeek V4 Pro 折算武力 62、智力维度天下第一——"丞相不以武力见长"反而被两种口径共同成全。
2. **带 \* 的 II 为 AA 标注的估算值**，清洗时保留原样，脚本按数值处理。
3. **三国志14数值为 PK 版**，含 DLC 与编辑模式示例武将（如"派翠夏"），共 1180 行。
4. **快照时效**：模型榜单月月翻新，本快照 2026-10-10 生效。"温酒斩华雄"在新快照里会不断重演。
5. **推理档位统一取最高**：模型名一律不带 max/xhigh/high/medium/low、with fallback 等档位后缀，数值取该基名下 II 最高的档位（`enrich_mapping.py` 自动处理）。版本日期（如 Qwen3.8 Max `(0902)`）、特供版（如 `(Daybreak Blue)`）、变体（如 `(non-reasoning)`）是名字本身，保留。
6. **漢獻帝不在三国志14武将册**（游戏不收录皇帝），其游戏五维为空是有意设定，非数据缺失。
7. **快照数据源与全量重建（2026-10-10 完成）**：首选方法为**单页全库**——`curl https://artificialanalysis.ai/leaderboards/models` 一次抓取，`rebuild_snapshot.py --leaderboard` 解析内嵌 `models` 数组（697 模型、687 有分，含 creator/II/成本/速度/延迟/TTFT 与 HLE、GPQA 等子分），一次 curl 即全量，无逐页成本。备选 sitemap 逐页模式（`--pages`，解析每页 slug 锚定对象，注意页面内嵌全库表须防串页）。II 为 1 位小数浮点、估算加 \*。**所有数值以内嵌 JSON 为准，人工手填一律作废；旧表导出（raw TSV）仅作历史留档。**
